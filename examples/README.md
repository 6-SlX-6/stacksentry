# Examples

| File | Purpose |
|---|---|
| [`insecure-compose.yaml`](insecure-compose.yaml) | Deliberately insecure stack: Docker socket mount, privileged container, published PostgreSQL port, plaintext password, missing restart policies and healthchecks, `latest` tags, writable bind mounts, host networking, no non-root users. **Do not deploy.** |
| [`reasonably-secure-compose.yaml`](reasonably-secure-compose.yaml) | Hardened Caddy + Gitea + PostgreSQL stack: pinned versions, restart policies, healthchecks, private networks, Docker secrets, non-root users, read-only filesystems, persistent database volume, no published database port. Only low-severity digest-pinning advice remains. |
| [`n8n-postgres-compose.yaml`](n8n-postgres-compose.yaml) | Realistic n8n + PostgreSQL stack with a few typical issues, used in [docs/examples.md](../docs/examples.md). |

[`reports/`](reports) contains the output of `stacksentry scan compose` for
these files in table (`.txt`), JSON and Markdown format. The reports are
regenerated by `make golden` with a fixed timestamp and verified by the test
suite, so they always reflect the current rules.

All credentials in these files are fake.
